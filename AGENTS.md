# Ground rules

These rules apply to all project-owned code in this workspace.

## Website translation requests

different target, follow [website/AGENTS.md](website/AGENTS.md). Reconcile the
English website content with Spanish and Brazilian Portuguese translations,
including missing pages, changed copy, translation paths, and link validation.
Do not ask the user to repeat the languages or workflow already defined there.

the C implementation rules below continue to apply to the native project.

## Implementation rules

- Minimize language sprawl: use C for implementation and substantive tests, and Bash for simple automation and test orchestration. Do not introduce another language without explicit user agreement. Python is prohibited, including one-off scripts and test tooling.
- Clean up task-owned scratch files, probes, temporary binaries, and intermediate logs before finishing. Use a task-owned temporary directory with an exit trap rather than scattering files in `/tmp/` or `build/`. Keep final requested artifacts and useful benchmark summaries in predictable locations; retain active dependency/toolchain caches. Never remove unrelated temporary files.
- Expand the shared OS interface when C tests need reusable OS functionality; keep test-specific helpers local to tests. Preserve existing test coverage when replacing tooling.
- Use PascalCase for functions. Keep names required by external APIs, such as C's `main`, unchanged.
- Use snake_case for types, typedefs, and struct tags.
- `<errno.h>` is permitted only for interacting with stdlib, never for internal error handling. Internal code defines its own per-function enums. Do not use errno constants, positive or negative, as internal result tags, return values, or control-flow conventions. Translate native errors at the API boundary; retained native codes are diagnostic data only.
- Use a function-specific tagged result struct for fallible operations, with a separate enum containing only that function's outcomes. Do not use one global result/error tag or encode failure in a negative integer, handle, or byte count. Check the tag before reading its payload, and translate outcomes explicitly when crossing function boundaries; never cast between result enums. Keep numeric errno and third-party status conventions at external API adapters, retaining native codes only as diagnostic payloads. Genuine predicates may return booleans; protocol status numbers and process exit codes belong at their external boundaries.
- Return information only when the caller can act on it meaningfully or needs it for program correctness. Otherwise return `void`, as with `HttpParserDestroy`. Do not add status returns that callers can only ignore. Preserve errors and results that affect correctness; this rule is not a reason to silently discard meaningful failures.
- Keep external code under `external/`: reusable backend code in `external/secure-backends` and shared foundational types in `external/common/types.h`.
- Use the shared numeric aliases (`u8`, `i32`, `f64`, `usize`, etc.) rather than redefining them locally.
- Use slices (a pointer named `ptr` plus a length named `len`) for all strings, buffers, and sequences throughout our code, including internal interfaces. Define typed slices as needed; do not use null-terminated strings as an internal representation.
- Slice lengths count elements, not bytes, unless the element type is a byte. Slices do not imply ownership or null termination; document ownership and lifetime where needed. A null pointer is valid only for an empty slice, and an empty slice must not be dereferenced.
- Convert slices to and from representations required by external APIs only at those API boundaries. Validate lengths and termination requirements there.
- Use `StringSlice` for string literals or character arrays, never pointers. Use `SliceFor(slice, index)` consistently when iterating over a slice instead of hand-writing its index loop; it captures the length once and supports empty slices, `break`, and `continue`.
- Avoid unsafe code in general: prefer interfaces that carry bounds and ownership information and validate operations before accessing memory. For example, replace unchecked `memcpy` calls and pointer-plus-length arithmetic with checked slice-copy and subslice helpers. Isolate unavoidable low-level operations in small shared primitives or external API adapters, document their preconditions, and test their boundaries. Do not bypass checks merely because current callers appear to provide valid inputs.
- Use the checked helpers in `external/common/slice.h` to obtain subslices and copy bytes: `ByteSliceSubslice`, `ConstByteSliceSubslice`, `ByteSliceCopy`, and `ByteSliceCopyRange`. Use `BytesOf` when copying an object's representation. Keep raw memory-copy operations inside these helpers rather than calling `memcpy` or `memmove` directly in application/parser code. Check both source and destination bounds without arithmetic overflow; failed copies must leave destination bytes unchanged, and overlapping copies must be supported. Slice bounds must describe live accessible storage, not uncommitted arena capacity.
- Keep parsed HTTP messages relocatable as one contiguous byte range. The root's `FirstHeaderOffset` and each `http_header`'s `KeyOffset`, `KeyLength`, `ValueOffset`, `ValueLength`, and `NextHeaderOffset` are fixed-width `u32` fields; every offset is relative to the root. Zero terminates the header list. Keep parser state and pointers outside the copyable message. Incremental header parsing must report consumed bytes and leave body bytes unconsumed.
- Keep the project build simple: use `build.sh APPLICATION_DIRECTORY` with direct compiler invocations, without project Makefiles or CMake. Vendored dependencies may use their upstream build tools internally. It will also compile reusable backend code when that code is added.
- Preserve vendored upstream code and licenses; project naming and slice conventions apply to our code, not third-party sources.
- Each deployment runs one application version, with the native host and all guest instances tightly coupled to that deployment's generated interfaces and ABI. Do not design for concurrently running application versions or cross-version guest compatibility. Recorded schema versions and migrations remain part of the deployment lifecycle.
- Keep all project-generated C sources and headers in `the consuming application’s src/generated/`, included in version control. Keep binaries, compiler dumps, and dependency/toolchain caches in `build/`. Regenerate source artifacts through the build rather than editing them manually.
- Each business route has an automatically generated header and a handwritten C implementation. Keep handwritten implementations outside `src/generated/`; generators must never overwrite them. Order route handlers by execution flow, using names such as `RouteProfile_Start` and `RouteProfile_GetProfile_Result`. Leaf handlers complete the response directly; do not generate a separate finish handler.
- The native C host owns transport and scheduling. HTTP parsing runs in a per-connection Wasm instance pinned to the connection's assigned worker; destroy that instance on connection teardown. The same instance will handle TLS when explicitly implemented; TLS is not implemented yet. Track ownership in a stable indexable arena with generation-tagged connection IDs. Use namespaced `CONNECTION_*`, `BROKER_*`, `SIGNING_*`, and `BUSINESS_*` message types; worker-to-host connection actions use `CONNECTION_REQUEST`.
- Keep thread interaction minimal. Prefer thread-owned state and bounded SPSC buffers with exactly one producer and one consumer per buffer. Use separate buffers for each direction, batch transfers, and define storage lifetimes explicitly. Do not share an I/O queue across threads.
- Keep one idle business instance per runtime per thread for synchronous jobs. After validating and copying the response, clear the entire current linear memory, restore its initial data image and admitted compiler global/table state, and replenish fuel before the next call. Retain grown memory; memory.size is the intentional difference from a fresh instance. Only reuse modules admitted by the conservative reset validator; unsupported modules use fresh instances. Discard instances after traps, invalid output, or reset failure. Thread exit releases its cache; join other runtime users before destroying the runtime. Keep connection instances pinned. Business jobs may execute locally or be dispatched by main to another worker (shared or separate business pool). Keep copied request storage stable through business completion and resume the connection only on its owner. Keep one active request/job per connection, preserving pipeline order. Connection guests own HTTP framing; business results may have an empty body.
- Use Wasmtime's pooling allocator for both connection and business runtimes, with separate engine-owned pools sized to the connection limit. Connection instances keep their connection lifetime; business instances additionally use the thread-local reset pool. Guest allocators remain append-only during a request; restoring initial business-instance memory at the request boundary also restores their initial cursors. Connection arena reset rules remain unchanged.
- Workers continuously spin on their incoming SPSC queues, without `pause`, scheduler yields, blocking waits, or eventfd notifications. The server's main loop polls both I/O completions and worker results without blocking.
- Default server worker count is the number of available physical P-cores. Select one allowed logical CPU per physical P-core and pin workers at thread creation, respecting the caller's affinity/cpuset. Explicit worker counts share those CPUs round-robin when necessary, without spilling onto E-cores. If P/E classification is unavailable, report the fallback to available physical cores; if only known E-cores are available, fail worker startup rather than silently using them. Inline mode and the main I/O thread retain their existing affinity.
- Keep arenas contiguous and never relocate their allocations. Host arenas reserve virtual address space and commit on demand. Each Wasm instance has one append-only backing allocator, the sole caller of memory.grow; that allocator has no free list, reuse, or rewind. An arena may extend only when its end still equals the global allocation end. The request arena resets its used cursor when starting the next request, after the previous request has been validated and copied out; retain backing storage, do not clear the arena or send a separate reset acknowledgement. Connection/TLS state and buffered pipelined bytes must live outside that arena. Reclaim Wasm memory by discarding the connection's instance.

## Extracted repository paths

This repository is Barework. Its generic host and guest sources are in `src/`,
and its compiler is `src/app_compiler.c` with supporting code in
`external/secure-backends/declaration/`. The consuming application owns its
`src/generated/` and `src/business/`. Run `./build.sh APPLICATION_DIRECTORY`;
run `./tests/run.sh` for the isolated regression fixture. Website instructions
from the original workspace do not apply in this repository.
